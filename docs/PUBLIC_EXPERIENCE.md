# TrustRx Public Experience — Launch Surface

## Job to be done

Give a state public-health leader, implementing partner, funder or technical
reviewer enough confidence to request a pilot briefing without presenting
TrustRx as a consumer health app, a surveillance replacement, or an already
deployed system.

## Product posture

TrustRx Public is a public, visual explanation of the system. It contains no
account sign-up, health-data intake, partner names, facility data, pilot
evidence, live dashboard, or unverified performance claims.

## Narrative architecture

1. **Hero — "The first signal should not wait for the internet."** Explain the
   offline-first public-health workflow. Primary action: `Request a pilot
   briefing`; secondary action: `Explore the system`.
2. **The field-to-reviewer visual.** A responsive animated-but-optional diagram:
   authorised reporter → SMS/USSD → private TrustRx core → integrity commitment
   → authorised reviewer → approved official-system handoff. Clearly label
   human review and private data boundaries.
3. **Trust, made concrete.** Three visual modules: offline-first reporting,
   private records with verifiable provenance, and human-authorised action.
4. **Institutional workflow.** Explain that TrustRx strengthens existing IDSR,
   SORMAS and DHIS2 workflows; it does not replace them. Do not claim a live
   integration until one is evidenced.
5. **The TrustRx surfaces.** Lite (reporting), Console (review), Verify
   (provenance) and Bridge (approved handoff), marked `in development` or
   `pilot-ready` only when supported by evidence.
6. **Pilot invitation.** A controlled contact route for public-health
   programmes and implementation partners, with a human follow-up commitment.
7. **Evidence and governance.** Public-safe architecture, privacy principles,
   security posture and clear non-claims.

## Visual direction

Use the user's references as principles, not copies: Dovetail's dark technical
depth, Attio/incident.io's editorial restraint, Customer.io's clear system
modules, and Profound's product-in-context framing. The signature visual is a
black-to-deep-indigo signal field with a single warm-alert accent, precise
typography, sparse gridlines, and real system diagrams rather than stock
photos. Respect `prefers-reduced-motion`; every animation is decorative and
optional.

## Acceptance criteria

- A visitor can state the product, user, privacy boundary and next action in
  under 90 seconds.
- The page makes no customer, deployment, clinical, regulatory or integration
  claim without evidence.
- It meets mobile, keyboard, contrast and reduced-motion requirements.
- It exposes no route for health-data submission.
- Copy and visuals pass founder, privacy and workflow-owner review before
  publication.
